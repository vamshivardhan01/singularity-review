# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project doesn't yet follow strict SemVer guarantees pre-1.0.

## [Unreleased]

### Added
- `CHANGELOG.md` (this file).
- **`node bin/cli.js check "<command>"`** — evaluates `guard.js`'s actual verdict (`DENY`/`ASK`/`ALLOW` + reasoning) on any command, no install and no state required. Lets anyone verify what the hook actually does before trusting it with a real `PreToolUse` hook. Wired into a CI smoke test.
- **`tests/liveness.sh`** — a mutation/liveness check for `tests/guard.test.js`: guts `evaluateCommand` to a no-op, re-runs the same 50-case suite against it via a new `GUARD_MODULE` override, and asserts the deny/ask cases actually go red. Proves the regression table is wired to real logic, not passing by construction. Wired into CI.
- README: a new headline section, [The One Part That's Not a Vibe](README.md#the-one-part-thats-not-a-vibe), with a real reproducible terminal transcript from the `check` command — moved ahead of "See It Catch Something" since `guard.js` is the one component in this system with a deterministic guarantee, not LLM judgment. Also: comparison against named generic AI code-review tools (CodeRabbit, Greptile, PR-Agent), a Discussions/first-issue call-to-action, and links to the previously-orphaned `wiki/Roadmap.md` and `wiki/FAQ.md` pages.
- `SKILL.md` (both `singularity-review` and `posting-review-comments`): a `Confidence: High | Medium` field on every finding, distinct from severity — severity says how bad if true, confidence says how sure the mechanism itself is. Findings now also get an explicit scope-creep check (does a diff do more than its stated purpose) and a consolidated final self-review gate before a report ships.
- `posting-review-comments`: inline PR comments now use a short bold title + minimal structure instead of a single run-on paragraph, capped hard at one body slot (a sentence, or at most 2 bullets in its place) so structure doesn't become its own form of bloat.
- `.github/workflows/pr-title.yml` — PR titles must follow Conventional Commits, documented in `CONTRIBUTING.md`.

### Fixed
- Author bio strengthened from a one-clause mood statement to a specific, checkable claim (see README).

### Security
- **This release supersedes 0.1.0, which shipped with a real bypass in `guard.js`'s hard-deny rules** (fixed in commit `3aeb41c`, included here): `DENY_RULES` matched only the literal command string, so `$(...)`, backticks, `${...}`, and a bare `$VAR` reference all silently bypassed every hard-deny rule (`terraform destroy`, `kubectl delete ns/pv`, force-push to main, etc.). A fail-closed check was added: a command mixing shell-expansion syntax with a keyword the deny rules care about now returns `ask` instead of silently allowing. **If you installed 0.1.0, re-run the installer** (`npx @vamshivardhan01/singularity-review`) once this is published.
- Found and fixed in this pass, not yet in a prior release: the fail-closed check above didn't recognize bash's special parameters (`$@`, `$1`, `$#`, etc.), so a shell-function wrapper (`function t() { terraform "$@"; }; t destroy`) still bypassed it. Closed by extending the expansion-detection pattern to match those too.
- `kiro/singularity-review.json`'s deny list was a hand-maintained second copy of `guard.js`'s rules and had already drifted (missing 3 rules). It's now generated by `scripts/sync-kiro-deny-list.js`, with CI failing the build if it drifts again. The generator's own known limitation — it can only derive Kiro's list from plain-regex `DENY_RULES` entries, not the 3 predicate-function ones (bare `terraform apply` without a plan, a stale plan file, force-push specifically to main/master) — is documented in the README's Risks section, not hidden.

### Fixed (continued)
- Adding the `check` command surfaced a real bypass-of-a-different-kind: `node bin/cli.js check "terraform destroy"` was itself getting denied by the hook, because `node` alone (as opposed to `node -e`) wasn't in `stripQuotedForMatch`'s list of commands whose quoted arguments are data, not a real invocation. Fixed by adding `check` to that list — safe because `check` never executes its argument, and an actual `$(...)`/`` ` ``/`$VAR` smuggled inside it is still caught independently by the raw-command expansion check.
- This changelog itself briefly described the stale-plan-file test gap (above) as still open in the same release that fixes it — caught reviewing this PR, corrected before merge.

### Testing
- Added `tests/guard.test.js`, a 50-case regression table for `guard.js`'s deny-rule matching, wired into CI. It started at 43 cases, all passing a `null` working directory — which meant the stale-plan-file predicate's actual filesystem check never executed during a test run despite the suite reporting green. Fixed in this same pass: added real temp-directory fixtures with controlled mtimes so that predicate is genuinely exercised, not just short-circuited past. Two more cases added alongside the `check`-command fix above.

## [0.1.0] — initial release

First published version. Known issue: the `guard.js` shell-expansion bypass described above shipped in this release — see Security notes above for the fix.
